# 01 — Project Overview

## Product

**XurPorisoy** is a native desktop audio-metadata editor written in Rust with `eframe`/`egui`. It is aimed at editing tags and embedded cover art for local music files, with an optional LLM lookup that fills in missing fields from a title and artist.

- **Repository:** `https://github.com/borneelphukan/xur-porisoy`
- **Author/maintainer:** Borneel B. Phukan
- **License:** MIT (declared in `Cargo.toml`, `installer/`, and the Debian copyright template)
- **Current version:** `0.0.1`
- **Primary platforms:** Linux (Debian/Ubuntu via apt repository) and Windows
- **Other platform:** macOS universal `.dmg`
- **Distribution:** GitHub Releases plus a signed (or explicitly trusted) apt repository on GitHub Pages

The name is a transliteration; the crate, binary, package, and config directory are all `xur-porisoy`.

## What the application does

| Capability | Summary | Main implementation |
|---|---|---|
| Add songs | Multi-select files through `rfd`; tags are parsed off the UI thread | `ui/state.rs::AppState::add_songs`, `ui/grid_view.rs`, `ui/mod.rs` |
| Library list | Virtualised table: `#`, title, artist, album, year, genre, track | `ui/grid_view.rs::show_list` |
| Library grid | Responsive cover-art tiles with a music-note placeholder | `ui/grid_view.rs::show_grid` |
| Detail editor | 18 tag fields plus a multiline lyrics editor, 65/35 split with artwork | `ui/detail_view.rs` |
| Tag read | `lofty` probe, properties disabled, primary/first tag, artwork fallback | `services/metadata.rs::read_metadata` |
| Tag write | Rewrites primary tag, deletes empty keys, strips selected extra keys, replaces art | `services/metadata.rs::write_metadata` |
| Cover art | Load/remove from disk; decode to a bounded thumbnail; cache texture | `ui/detail_view.rs::show_album_art`, `services/images.rs`, `ui/state.rs::TextureCache` |
| LLM fill | Any OpenAI-compatible chat-completions endpoint; prompt asks for JSON | `services/llm.rs`, `ui/detail_view.rs` |
| Cover lookup | iTunes Search API; rewrites 100×100 artwork URL to 600×600 | `services/artwork.rs` |
| LLM test | Sends a one-line "Reply with OK" request | `services/settings_view.rs`, `services/llm.rs::test_connection` |
| Themes | System / Dark / Light, applied live and persisted | `ui/mod.rs::apply_theme`, `models/song.rs::ThemePreference` |
| Settings | LLM credentials, last folder, window size, theme | `services/settings.rs` |
| About/error | Centered egui windows | `ui/mod.rs::show_about_popup`, `show_error_popup` |

## Deliberate boundaries

- **Local files only.** There is no media library database, scanning daemon, or cloud sync.
- **Tag editing, not audio editing.** Audio properties (bitrate, sample rate, duration) are never read or displayed; `ParseOptions::read_properties(false)` is deliberate.
- **No MusicBrainz/Discogs client.** The only network calls are the configured LLM endpoint and the iTunes Search API.
- **No background save queue.** Saves happen on the UI thread.
- **No auto-update.** Unlike some sibling projects, there is no update checker in this codebase.
- **No fuzzy matching or duplicate detection.** Duplicate paths are simply added again.
- **No test suite beyond two unit tests** in `models/song.rs` (serde round-trip and LLM-response parsing).
- **No marketing website.** The Pages site is an apt repository landing page generated by `packaging/apt/build-repo.py`.

## Technology stack

From `Cargo.toml` (edition 2021):

| Crate | Version | Role |
|---|---|---|
| `eframe` | `0.29` (`persistence`, `default_fonts`, `glow`, `wayland`, `x11`) | Native window and egui integration |
| `egui` | `0.29` | Immediate-mode GUI |
| `egui_extras` | `0.29` | Virtualised table (`TableBuilder`) |
| `winit` | `0.30` | Restores `winit/default` features after eframe defaults are disabled |
| `lofty` | `0.25` | Audio tag parsing/encoding and embedded pictures |
| `reqwest` | `0.12` (`json`, `rustls-tls-webpki-roots`) | LLM and iTunes HTTP |
| `serde` / `serde_json` | `1.0` | Settings, LLM payloads, model serialisation |
| `tokio` | `1.40` (`rt-multi-thread`, `macros`) | Async runtime for LLM/artwork |
| `directories` | `5.0` | Platform config directory |
| `image` | `0.25` (png, jpeg, gif, bmp only) | Icon loading and cover-art thumbnails |
| `rfd` | `0.17` (`xdg-portal`) | Native file dialogs |
| `thiserror` | `1.0` | `AppError` |
| `winresource` (build) | `0.1` | Windows icon and version resource |

Notably **not** present: `rayon`, `wgpu`, OpenSSL, any logging crate, any analytics, any test framework.

Feature choices that matter:

- `eframe` defaults are off. `glow` is the renderer, `persistence` keeps window state, and the explicit `winit` dependency restores Wayland dynamic loading and client-side decorations.
- `accesskit` is off because on Linux it pulls the zbus/atspi stack and a `quick-xml` release with advisories.
- `image` defaults are off so AVIF/EXR/TIFF/WebP decoders are not compiled in.

## Runtime prerequisites

- A supported audio file (MP3/ID3v2, FLAC/Vorbis, OGG/Vorbis, M4A/MP4, WAV, AIFF, APE).
- On Linux, the X11/Wayland/GL/DBus libraries listed in the Debian `Depends` field. They are `dlopen`ed at runtime, so `ldd` does not reveal them.
- No separate codec or metadata binary is required; `lofty` is statically linked.
- For LLM fill: network access to the configured endpoint. For cover art: network access to `itunes.apple.com`.

## High-level runtime shape

```text
main()  [tokio::main(worker_threads = 2)]
  └─ eframe window (glow)
       └─ XurPorisoyApp
            ├─ AppState (songs, view, settings, texture caches)
            ├─ std::thread "library-loader" ──► AppMessage::SongLoaded
            ├─ tokio::Handle::spawn ──────────► AppMessage::MetadataFetched
            │                                   AppMessage::LlmTestResult
            └─ Receiver<AppMessage>, drained every frame
```

## Where the product is heading

The code and workflow show emphasis on:

- efficient large-library browsing (virtualised list, capped texture caches, background tag loading);
- broad Linux packaging (Debian, RPM, AppImage, Flatpak, Arch, RISC-V) and an apt repository;
- a minimal, dependency-light build (no wgpu, limited image decoders, rustls);
- LLM-assisted tagging that works with local and hosted OpenAI-compatible servers.

There is no changelog in the repository. Release history is the GitHub Releases page and the git log.

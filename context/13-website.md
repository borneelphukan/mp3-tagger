# 13 — Website and GitHub Pages

There is **no marketing website** in this repository. A commit titled "chore: remove the website" (`f880dbc`) removed it. GitHub Pages exists solely to host the apt repository and `install.sh` generated by `packaging/apt/build-repo.py`.

## 1. What is published

On every non-PR run of `release.yml` (and on the weekly schedule), `publish-pages` builds and deploys a static tree:

```text
pages/
├── index.html                          generated landing page
├── install.sh                          copied from packaging/apt/install.sh
├── xur-porisoy-archive-keyring.gpg     signed runs only
├── UNSIGNED                            unsigned runs only
└── apt/
    ├── dists/stable/
    │   ├── Release
    │   ├── Release.gpg                 signed runs only
    │   ├── InRelease                   signed runs only
    │   └── main/binary-amd64/
    │       ├── Packages
    │       ├── Packages.gz
    │       └── Packages.xz
    └── pool/main/x/xur-porisoy/
        └── xur-porisoy_<version>_amd64.deb
```

Because CI only downloads the `Debian package (x86_64)` artifact, the live repository is **amd64 only**. The pool letter comes from the first character of the package name (`x`).

| Purpose | URL |
|---|---|

| Install script | `https://borneelphukan.github.io/xur-porisoy/install.sh` |

| Pool | `https://borneelphukan.github.io/xur-porisoy/apt/pool/main/x/xur-porisoy/` |

`REPO_BASE` is hard-coded in `packaging/apt/build-repo.py` (`https://borneelphukan.github.io/xur-porisoy`), and `install.sh` uses the same default with `XUR_PORISOY_REPO_URL` as an override. Forks must change both.

## 3. Landing page contents

`build_index_html` writes a dependency-free HTML page with system fonts and inline CSS. It includes:

- Heading "XurPorisoy apt repository", plus "(unsigned repository)" when applicable.
- Suite, component, and architecture line.
- The one-line install:

  ```bash
  curl -fsSL https://borneelphukan.github.io/xur-porisoy/install.sh | sudo bash
  ```

- A manual setup block:
  - download the keyring (signed) or the comment `# no signing key: the repository is used with [trusted=yes]`,
  - write `/etc/apt/sources.list.d/xur-porisoy.sources` in deb822 format,
  - `sudo apt update`,
  - `sudo apt install xur-porisoy`.
- A direct link to the pool directory.

There are no screenshots, download buttons for other platforms, changelog, or links to the GitHub Releases page. Those live only in the root README and GitHub.

## 4. Install script

`packaging/apt/install.sh` is copied verbatim to the site root by the Python builder and made executable. Behaviour:

1. Parses `--print/-n`, `--remove`, `--yes/-y`, `--help/-h`.
2. Probes the keyring URL; if reachable, uses `Signed-By: /usr/share/keyrings/xur-porisoy.gpg`; otherwise uses `Trusted: yes` and prints a notice.
3. In install mode, re-execs with `sudo` if not root. Dry-run never re-execs.
4. Downloads the keyring atomically (`*.tmp` then `mv`, mode 0644) when signed.
5. Writes the sources file atomically (`.tmp` then `mv`).
6. Runs `apt-get update` and `apt-get install [-y] xur-porisoy`.
7. In remove mode, deletes the sources file and keyring (the package stays installed) and prints the `apt remove` command.

It intentionally never reads stdin, so `curl | sudo bash` works. `--print` still contacts the keyring? No: in dry-run it skips the probe and prints "(dry run: not contacting ...)". It then prints a `cat > sources` heredoc instead of writing.

## 5. Build locally

```bash
cargo build --release --locked
packaging/debian/build-deb.sh
python3 packaging/apt/build-repo.py \
  --debs dist --out pages \
  --suite stable --component main \
  --origin xur-porisoy --label "XurPorisoy"

# signed (optional)
python3 packaging/apt/build-repo.py \
  --debs dist --out pages \
  --suite stable --component main \
  --origin xur-porisoy --label "XurPorisoy" \
  --gpg-key-id <KEYID> \
  --gpg-key-file repo-key.asc \
  --gpg-passphrase-file passphrase.txt

# preview
python3 -m http.server 8000 --directory pages
```

Open `http://localhost:8000/`. `install.sh` defaults to the production URL, so test it with:

```bash
XUR_PORISOY_REPO_URL=http://localhost:8000 sh pages/install.sh --print
```

Signing note: `--gpg-key-file` is imported into the runner's keyring, and `--gpg-passphrase-file` is only used when non-empty. `build-repo.py` calls `gpg --batch --yes`; with a passphrase it adds `--pinentry-mode loopback`. A successful signed run exports the public key next to the site.

## 6. Deployment workflow

From `release.yml`:

1. `needs: [ci, debian-x86_64]`.
2. Runs only when `!cancelled()`, event is not `pull_request`, the Debian job succeeded, and the quality gate succeeded or was skipped (the weekly schedule skips `ci`).
3. Downloads the amd64 `.deb`.
4. Optionally writes the GPG key/passphrase from secrets to `$RUNNER_TEMP/apt-signing` with mode 0600.
5. Builds `pages/` and verifies the Release fields and SHA256 entries.
6. `actions/configure-pages@v5` with `enablement: true` (creates the Pages site on first run).
7. Uploads the artifact and deploys with `actions/deploy-pages@v4`.
8. Writes the deployed URL and install command to the job summary.

Permissions for that job: `contents: read`, `pages: write`, `id-token: write`; environment `github-pages`.

### First deployment

If `enablement: true` fails (restrictive org policy), enable Pages manually under **Settings → Pages → Build and deployment → GitHub Actions**, then re-run the workflow.

## 7. Signed vs unsigned

| State | Files | Client configuration |
|---|---|---|
| Signed | `InRelease`, `Release.gpg`, keyring `.gpg` | `Signed-By: /usr/share/keyrings/xur-porisoy.gpg` |
| Unsigned | `UNSIGNED`, `Acquire-By-Hash: no` | `Trusted: yes` |

Signing is enabled when `vars.APT_REPO_KEY_ID` and `secrets.APT_REPO_PRIVATE_KEY` are present. The passphrase is optional (key may be unprotected). Missing material produces a warning and an unsigned repository; the workflow does not fail.

## 8. What is *not* on the site

- No source documentation, no user manual beyond the root README shipped in packages.
- No direct Windows/macOS/AppImage/RPM download links (use GitHub Releases).
- No analytics, cookies, fonts, JavaScript, or external CSS.
- No version history or changelog.
- No custom domain; the default `github.io` URL is assumed by all scripts.

## 9. Gotchas

- Changing the repository URL requires editing **both** `REPO_BASE` in `build-repo.py` and the default `BASE_URL` in `install.sh`; the Cargo `homepage`/`repository` are unrelated.
- The Pages site is replaced wholesale on each deploy; there is no incremental state and no retention of older `.deb` files. Each deploy contains only the version built in that run.
- The apt `Release` file is regenerated on every deploy, so clients must run `apt update` after a new release.
- GitHub Pages may serve stale content briefly after a deploy (CDN); the workflow prints the URL but performs no cache-busting.
- `index.html` is generated, never hand-edited. Edit `build_index_html` instead.
- The install script trusts the keyring solely because it was fetched over HTTPS from the same origin as the repository; there is no independent key fingerprint check.
